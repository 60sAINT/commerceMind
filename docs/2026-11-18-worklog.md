### 3. 行为说明

**Markdown 安全边界：** 只对助手消息启用 Markdown；用户消息仍按纯文本 `whitespace-pre-wrap` 展示，避免把用户输入当 Markdown 结构解析。链接强制新窗口并阻断 opener/referrer；代码块复制使用高亮后的文本递归提取，不依赖 DOM 选择器。

**输入与发送：** 发送仍由 `App` 统一处理：没有 session 时先创建，再走 `send`；编辑失败消息走 `editAndResend`。输入框只负责键盘语义、自动增高和长度限制，不直接调用 store，便于以后替换布局。

**智能滚动：** 滚动容器自己记录 `stickRef`，新消息/流式增量只在接近底部时跟随；用户上滑阅读时出现“回到底部”。流式阶段用 `auto` 滚动避免 smooth 动画堆积。

**健康状态：** 挂载时检测一次，之后 30s 轮询，并在窗口聚焦、页面可见性变化时补检。顶栏显示模型名与状态点；`degraded` / `offline` 时消息区顶部出现告警条，可直接重新检测。侧栏连接状态与顶栏共用同一份 store。

**失败收尾：** 生成中失败与用户主动中断使用同一套 `partial-*` 展示策略；失败的用户消息保留“重试 / 编辑”入口，重试或改文重发前按 `requestId` 清掉上一轮的 `stream-*` / `partial-*`，避免新旧回答叠加。

### 2. 程序初始化：按时间顺序加载已有 Skill

1. 进程启动，`load_dotenv()` 加载环境，`Settings.from_env()` 读取 skills.enabled/debug、根目录和预算。Compose 将宿主机 `./skills` 可写挂载至 `/app/skills`；初始化看到已有技能，后续上传也写回这里，不进 PostgreSQL。
2. `create_app()` 中，enabled=false 则不创建管理器；enabled=true 则创建严格 frontmatter 模式的 `SkillManager`，调用 `manager.load()`，内部执行一次 `reload()`，不等第一轮聊天才加载。
3. `reload()` 用 `_reload_lock` 串行化本管理器的扫描，取得旧快照和下一版本号，扫描 `*/SKILL.md`。隐藏 `.staging-*`、`.trash-*` 不进入目录；符号链接或越界入口拒绝加载。
4. 只读取入口 YAML frontmatter，遇闭合分隔符即停，提取 name、description、keywords、version、enabled，ID 来自目录名。要求非空 name/description；enabled=false 不收录。错误放入 errors，不妨碍其他合法技能。**启动扫描不读正文、不读资源内容。**
5. 构建不可变 SkillCatalog，与旧快照计算 added/updated/removed/unchanged，生成含 count、errors、version、loaded_at、duration_ms 的报告。初始版本 0，首次加载后为 1。
6. 在 `_lock` 内一次交换 `_catalog/_last_report/_version`，清空正文 `_body_cache`。原子性指进程内目录快照交换，扫描期间旧读取不会看到构建了一半的目录。
7. enabled 和 debug 同时为 true 时注册上传、文件管理和 reload 接口；否则管理接口 404，前端只读。`GET /skills` 读取当前快照，返回元数据、management_enabled、limits；本身不重新扫描、不读取正文。
8. 前端共享 skills store 获取目录，技能列表与输入框 `/` 候选使用同一份结果。聊天中 `_build_skill_system()` 注入轻量目录（ID、名称、描述）；手动 slash/skill_ids 选择跳过自动选技，无手动选择时按 description 调模型选技。
9. 只有选中 ID 才 `manager.load_skill()` 读取正文，按正文字符预算截断，加入回答模型的 system prompt；原有 state、短期记忆与用户问题链路保持。资源只列清单，不自动读入聊天 prompt，scripts 不执行。
10. 正文缓存按入口路径与 `(mtime_ns, size)` 复用；reload 清空缓存。读取期间若快照改变，旧读取不把缓存写回新快照。已构造并发给模型的 prompt 不被后续上传或删除追溯替换。

### 3. 新上传技能：浏览器到后端的时间顺序

1. 打开技能面板，`GET /skills` 获取当前列表、管理权限与预算。界面只有上传入口和已启用技能列表；没有原来的“新增文件”“管理文件”等编辑入口。
2. 用户选择一个 SKILL.md 或 ZIP。浏览器只检查扩展名与原始文件大小，不在浏览器实现 ZIP 解压或复杂 frontmatter 解析，不新增 ZIP 前端依赖。
3. 前端发 `POST /skills/upload/preview?filename=...`，请求体为原始文件字节（application/octet-stream），不是把所有文件转为 JSON，也不需要 multipart 依赖。API 分块接收，累计超过整包预算立即 413，随后把解析/校验交给线程。
4. 单文件必须命名 SKILL.md，严格按 UTF-8 解码；从 frontmatter 的 name 推导技能 ID。新上传的 name 只允许小写字母、数字、连字符，1–64 字符。**现有中文展示名称、下划线 ID 的技能继续由旧加载器规则兼容，不迁移或重命名。**
5. ZIP 必须只有一个根技能文件夹，其下有 SKILL.md；例如 my-skill/SKILL.md、my-skill/references/a.md。直接把 SKILL.md 放在 ZIP 根、多技能根目录、根目录名与 name 不一致均 422。忽略 Finder 的 __MACOSX 和 .DS_Store 辅助元数据，其他隐藏路径拒绝。
6. 用 Python zipfile 逐条检查 ZIP 元数据和受限读取，拒绝目录穿越、绝对路径、反斜杠、符号链接/特殊文件、重复条目、加密或不支持/损坏 ZIP。资源限 references/、templates/、scripts/ 下的 UTF-8 文本。既约束压缩包原始字节，也约束解压后单文件/总大小/文件数；不使用 extractall 将上传路径直接解压到磁盘。
7. 复用安装层 `_prepare_files()` 统一校验，将文件写入系统临时目录，使用独立的严格 SkillManager 扫描并尝试读正文，验证 name、description 与非空正文。**管理预校验会读正文，但启动扫描不读正文。** 临时目录完成后自动清理，正式 skills 目录和当前在线快照不变。
8. 同名已有技能返回 409，不静默覆盖。校验通过仅返回 `{skill, file_count, total_bytes}`；界面展示名称、描述、文件数和“格式校验通过”，此时可以取消，还未启用。
9. 用户点击“上传并启用”，前端把同一文件再次发 `POST /skills/upload?filename=...`。后端重新校验，不能只信任前一次预览；同名安装并发最终由安装锁与存在性检查保护。
10. 安装逻辑在 asyncio.to_thread 内执行，持有进程内 `_install_lock`。先在正式根目录下创建隐藏 `.staging-<uuid>/<id>/`，写入并再次预校验，再 rename 到 `skills/<id>/`。新上传接口固定只创建，不覆盖；之前的 JSON 显式 overwrite 接口保留兼容，前端不调用它。
11. 安装成功后内部调用正式 `manager.reload()`：扫描 frontmatter、计算目录变化、交换快照、清空正文缓存。确认新 ID 能从在线目录查到后返回 `{skill, report, revision}`。**前端不会再重复 POST /skills/reload。**
12. 前端显示“已上传并启用”，清理本次选择，`GET /skills` 更新共享列表和 `/` 候选。下一轮选中该技能时重新加载正文进入 prompt。若安装成功而列表刷新失败，会提示刷新失败，不把安装成功误报为保存失败。
13. 文件经 `./skills:/app/skills` 写回宿主机，重建容器后保留；不会修改已有聊天 turn、回执或记忆。

### 4. 接口、删除与失败分支

| 接口 | 使用时机与行为 |
| --- | --- |
| GET /skills | 页面/面板加载、上传或删除后刷新；读取当前快照与管理能力，不扫描磁盘 |
| POST /skills/upload/preview?filename=... | 原始 .md/ZIP 字节，验证后返回 skill/file_count/total_bytes；不安装、不发布、不执行脚本 |
| POST /skills/upload?filename=... | 用户确认后重新校验并创建，内部安装+reload，返回 skill/report/revision；同名 409 |
| GET /skills/{id}/files | 保留完整包读取；前端删除前内部读取 revision，不向用户展示文件树 |
| DELETE /skills/{id}?revision=... | 用户确认删除后调用；锁内复核 revision，目录移入隐藏备份、reload、成功后清理备份 |
| POST /skills/reload | 用户在本地磁盘改文件后手工触发；线程内与文件管理串行，随后 GET 同步列表 |
| POST /skills/import、PUT /skills/{id}/files | 保留已有 JSON 创建/编辑兼容能力，前端本版不再使用 |

- 上传中的按钮禁用重复操作；校验请求支持卸载取消和代次校验，防止旧响应污染界面。正式安装开始后不把客户端断开视为文件事务取消信号，超时/断网应先刷新列表确认结果，再决定重试。
- 同名冲突显示错误。更新技能的简化交互为本地修改后重新打包、先确认删除旧技能再上传；不再提供在线逐文件编辑或静默覆盖。
- 删除前确认；读完整包取得内容 revision，再带 revision 删除。期间其他管理操作改了文件则 409，避免读后再删发生竞态。删除不影响已保存聊天记录。
- 非法输入不触碰正式目录。安装/删除或 reload 异常返回明确错误，尽力恢复旧目录并 reload；若恢复也失败则保留备份并记录日志，不承诺文件系统事务原子性。JSON 覆盖采用备份后 rename，两次 rename 之间可能有路径短暂空隙。
- 当前实现为格式、路径、资源类型与压缩包预算校验，**没有恶意语义扫描、人工审核队列，也不会假装完成这些检查**。脚本保存但不执行。
- 预算沿用现有配置：默认单文件 64KiB、整包 1MiB、64 个文本文件，不照搬其他产品的 30MB 额度。ZIP 原始大小和解压后大小都受限，避免只检查压缩体积。
- 没有文件系统 watcher；UI 上传/删除内部自动 reload，直接修改磁盘后需点击重新加载。目录 version 是单进程内递增，重启重新初始化；SHA-256 revision 是整个文本包内容版本，二者不同。
- 目录 diff 主要依据 SKILL.md 元数据/stat，不是逐资源内容 diff；一次 reload 清空所有正文缓存。仅作用当前进程，线程锁不协调多 worker/多副本或外部程序直接改盘；需逐进程重载或另做广播。已发出的 prompt 不变，并发准备 prompt 遇目录切换仍可能走技能不可用错误路径。
