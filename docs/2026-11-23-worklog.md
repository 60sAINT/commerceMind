## 第一件事：T4 工具结果 TTL 缓存

完成 `ToolManager.execute()` 的进程内 TTL 缓存。以订单查询为例，同一用户在 TTL 内再次用相同参数查询，会直接拿到上一次成功的结果。不同用户各自查询。同一用户跨会话能否复用，由工具声明的 `cache_scope` 决定，默认按 `user_id` 隔离。

- 参考 EchoMind，用工具名和规范化参数、上下文范围、缓存版本以及适用的重排数量计算缓存键。缓存按单调时钟过期，读写时深拷贝数据，容量满时按插入顺序淘汰最早的一批条目。
- 参数校验先于缓存。只读工具可用正数 `cache_ttl_s` 开启缓存，`use_cache=False` 可让单次调用跳过读写。只有成功结果会写入缓存，命中计为一次逻辑成功，物理尝试数保持不变。
- 可按工具或清空全部缓存。失效时递增版本，旧调用即使随后成功也无法回填。注销工具同步清除缓存，`fork()` 从空缓存开始。
- 熔断尚在冷却期时允许复用有效缓存。达到恢复时间后，即使缓存有效，请求也会进入实际执行路径，为 T5 的半开探测留出机会。探测名额和熔断结果由 T5 的执行链路接管。

缓存、工具管理器、参数校验、超时重试和工具配置共 170 项测试通过。全量测试未运行，当前 Windows Python 环境缺少项目锁定的 `chroma-hnswlib==0.7.6` 预编译包，依赖安装未成功。

## 第二件事：T5 工具熔断与降级

`ToolManager.execute()` 现在按工具维护熔断状态。主调用最终超时或 handler 失败时，无论内部尝试几次，熔断器只记一次失败。参数错误、调用前已耗尽预算、请求取消和熔断拒绝均不增加熔断失败次数。管理器默认连续失败 5 次后打开熔断，冷却 60 秒。这两个值可在构造管理器时传入。

- 冷却期内仍可返回有效缓存。冷却结束后，第一个请求绕过缓存，只执行一次半开探测。并发请求可使用有效缓存或走降级。探测成功后恢复正常，探测失败则重新冷却。探测取消后，下一次请求可以接手。旧调用的迟到结果不会关闭新一轮熔断或回填缓存。
- 主路径最终超时、handler 失败或熔断拒绝时，可运行已注册的 `fallback`。降级只尝试一次，等待时间受工具超时和剩余阶段预算限制。有数据时返回 `success=False, usable=True, degraded=True`，保留主路径错误码。降级失败或返回 `None` 时，结果不可用。降级数据不写缓存。
- `get_stats()` 增加熔断拒绝和成功降级次数。降级返回可用数据时，主路径仍计为失败。

工具层 179 项测试通过，覆盖逻辑调用计数、并发半开探测、取消、迟到结果、缓存和降级边界。全量测试仍受上述 Windows 依赖限制。

## 第三件事：T6 工具结果重排

在 `ToolManager.execute()` 接入可注入的 `Reranker`。默认关闭。调用方可以用 `build_reranker(settings, llm)` 按配置装配 LLM 重排器，并在执行时传入 `settings.rerank_top_k`。工具需通过 `supports_rerank` 声明支持重排，并用 `rerank_query_field` 指定查询字段。候选列表超过 K 条且查询非空时才请求重排。

- 给候选编号，让模型返回相关性排序后的索引。校验索引范围，去除重复项，并按原序补齐遗漏项。最终数据从工具返回的原始候选中选取。
- 重排受工具超时和工具阶段剩余预算约束。异常、超时或无效输出时返回原序前 K 条，主工具调用仍算成功。临时返回的原序结果不写入缓存，后续调用仍可尝试重排。
- 成功重排后按 Top-K 分开缓存，命中保留 `reranked=True`。此处只接入工具层，应用装配随 SSE 接入完成。

工具层 189 项测试通过，包含模型索引校验、按 Top-K 缓存、关闭重排和超时回退。全量测试仍受上述 Windows 依赖限制。

## 第六件事：T9 Function Calling 主循环

新增 `tooling/function_calling.py`，通过 `FunctionCallingLoop(llm, manager, settings)` 串起模型与工具。`stream(message, context, history=..., system=..., allowed_tools=...)` 返回结构化的 `delta` 和 `done` 事件，工具事件由 `stream_events` 控制；`run()` 汇总为结果，供脚本和评测直接调用。这里不生成 SSE 文本，也不改 API 和记忆写入。

- `should_use_tools()` 按开关、trigger 和当前意图决定是否进入工具阶段。关闭或不匹配时，保持普通流式回答。
- 工具阶段使用非流式 `create_message()`。模型直接给出文本时立即输出，不再请求一次模型。收到工具调用时保留 assistant 原始消息块，统一通过 `ToolManager.execute()` 执行，再为每个调用 ID 回传一条 `tool_result`。参数错误附带 schema hint，模型可在下一轮修复。
- 轮数、每轮调用数、总调用数和工具阶段预算都使用现有配置。超限调用不执行，仍回传对应错误，避免留下没有结果的调用块。达到上限或预算后，通过关闭工具调用的 `stream_message()` 流式收尾；最终生成受 LLM 客户端自身超时约束。
- 调用白名单同时控制模型可见定义和实际执行。相同工具、规范化参数的重复调用不会再次执行。消息、去重集合、预算和 trace 都是请求局部状态。
- 工具结果保留 success/usable/degraded、缓存和重排标记。业务结果自身为失败时，回传模型的 `is_error=True`。超长结果改为带截断标记的文本预览，序列化后仍是合法 JSON，并受字符上限约束。
- 请求取消原样传播，关闭流时释放上游迭代器。LLM 失败时返回确定性的限制说明，已输出的片段不会重新生成，工具也不会重新执行。

LLM、内置工具、工具执行层与主循环共 252 项测试通过，其中 T9 新增 19 项，覆盖参数修复、消息配对、各项限额、重复保护、并发隔离、截断和取消。token 用量目前累计非流式工具阶段，现有流式接口不提供最终回答的 usage。T10 继续负责协议回退及工具调用容错专项，T11 负责 SSE 接入。全量测试仍受上述 Windows 依赖限制。本次未提交。

## 第七件事：T10 工具调用容错专项

补齐从模型协议、参数校验、依赖失败到最终回答的容错链路。

- **非法工具响应整轮拒绝。** 缺 ID/工具名、参数不是对象、参数包含非有限数字、重复 ID、工具块被截断或停止原因不一致，都不会执行该轮的任何工具。模型收到不含非法块的修复提示，可在既有 max_rounds 和阶段预算内重试；跨轮重复使用调用 ID 也会被拒绝。
- **参数错误只走修复。** 缺必填、类型错误、多余字段、枚举和范围越界都回传 invalid_arguments 和 schema hint，不重试、不计熔断。结果中的 repairs 记录协议或参数修复提示次数。
- **依赖失败按逻辑调用计数。** 超时、handler 异常由执行层处理，只读工具有限重试；副作用工具不自动重试。重试最终失败只增加一次熔断失败计数，熔断拒绝不执行 handler。降级结果保留 success/usable/degraded 和主路径错误码。
- **重复调用保护覆盖规范化参数。** 忽略对象字段顺序、字符串首尾空白及 1/1.0 的表示差异，同一请求不会因改调用 ID 或调整 JSON 写法再次执行同一操作。执行前登记调用，即使首次操作失败也不会自动重放副作用。
- **明确的协议不支持才回退。** LLM 适配器识别 400/422/501 中明确拒绝 tools、tool_choice 或 function calling 的响应。普通参数错误、工具 schema 错误和服务故障不触发协议回退。protocol_fallback 开启时切换为纯文本消息，保留已完成的工具记录，不重跑工具；关闭时直接返回安全兜底。
- **回退有界，最终失败不泄漏异常。** 最终流式请求只有在尚未输出文本时才允许一次纯文本回退；纯文本也失败时终止。若已输出片段，补充确定性的限制说明，不重新生成。适配器异常和流中断也转为安全结果，取消仍原样传播。不可序列化的工具数据回传 invalid_result；结果截断后仍保留状态与错误码。

LLM、内置工具、执行层和编排共 303 项测试通过，其中容错专项新增 51 项。全部使用本地替身和真实 SDK 异常对象，不请求外部模型。全量测试仍受上述 Windows 依赖限制。本次未提交，T11 继续负责 SSE 接入。

## 第八件事：T11 SSE 接入

`/chat/stream` 现在可以通过现有 SSE 协议运行 Function Calling。应用创建时按工具配置注册 EchoMind 对齐的 8 个内置工具，工具管理器在进程内共享。构建失败时退回普通聊天，开关关闭时不创建管理器。

- 统一有记忆和无记忆的生成入口。工具 auto 模式优先采用当前意图结果；意图识别未启用或失败时，使用当前消息的本地规则判断是否进入工具循环，不要求 Redis 可用。
- 给工具传入当前用户、会话、请求 ID、意图、置信度、实体和上下文可用性。已选 Skill 正文、历史消息和摘要沿用原有注入流程。
- 非流式工具往返期间不输出内部消息。最终回答仍输出 delta，模型直接回答时不再请求一次。stream_events 开启时额外输出 tool_start/tool_end；done 带工具摘要和成功状态，debug 开启时附带不含参数和数据的 trace。
- 只将完整且成功的最终回答提交 PostgreSQL / Redis。安全兜底仍能返回给用户，但标记失败且不写入成功问答或幂等回执。工具消息和结果不落入聊天历史。幂等重放不再执行工具。
- 会话锁现在覆盖读取、工具往返、最终回答和提交。取消会关闭上游迭代器、取消在途工具并释放锁，不保存半成品；无记忆路径同样检查断连。

补齐临时测试环境的 Web、Redis 和 tokenizer 依赖后，以 UTF-8 模式验证：T11 新增 16 项，聊天、Skill、LLM 与工具相关回归共 410 项通过。全量运行为 700 项通过、4 项跳过、4 项失败；已加载修改前 HEAD 的 API 复测这 4 项，全部复现，分别涉及后台画像队列、Skill 文件换行、Windows 符号链接权限和 ZIP 路径测试，与 T11 改动无关。本次未提交。

新增结构化日志 `tool_call`、`tool_result`、`function_calling_completed`，通过本次请求 ID 关联。工具执行日志和编排结果日志分开记录，能定位未执行的拒绝调用和结果序列化错误。只记录状态、错误码、计数和耗时，不记录消息、参数、业务结果、用户/会话标识或异常正文；未知工具名使用固定占位符。聚合器不保留请求 ID 或单次 trace，延迟样本有界。
