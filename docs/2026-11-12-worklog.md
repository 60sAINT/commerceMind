### 新增文件说明

#### `core/skill_loader.py`

- **作用**：发现 `skills/<skill_id>/SKILL.md`，只解析目录需要的轻量元数据，不加载正文和资源。
- **大概流程**：
  1. `SkillManager(root_dir)` 保存并解析根目录；
  2. `load()` 扫描 `skills/*/SKILL.md`；
  3. 只读文件头，解析 front matter；
  4. 校验 skill id、符号链接、名称和描述；
  5. 生成 `SkillDescriptor`，组装成 `SkillCatalog` 快照。
- **输入**：Skill 根目录路径 + 磁盘上的 `SKILL.md` 文件头。
- **输出**：`SkillCatalog`，包含 `skills`、`errors`、`version`、`loaded_at`。
- **上游**：后续由 `SkillSettings` / API 启动流程创建并调用 `load()`；热重载时也会再次调用。
- **下游**：为 `/skills` 调试接口、system prompt 轻量目录、正文按需加载和资源读取提供元数据。
- **边界**：本文件当前不读正文、不读 `references/templates/scripts`、不执行脚本。

### 数据结构

| 类型              | 作用                                                            |
| ----------------- | --------------------------------------------------------------- |
| `SkillDescriptor` | 单个 Skill 的轻量元数据，不含正文                               |
| `SkillError`      | 单个 Skill 的解析错误，使用相对路径                             |
| `SkillCatalog`    | 一次扫描得到的目录快照，包含 skills、errors、version、loaded_at |
| `SkillManager`    | 扫描根目录、解析 `SKILL.md`、替换目录快照                       |

`SkillDescriptor` 包含：

```text
id / name / description / keywords / version / enabled
relative_path / path / mtime_ns / size
```

对外 `to_summary()` 只暴露：

```json
{
  "id": "billing_support",
  "name": "账单退款处理规范",
  "description": "处理退款、扣款、发票和订阅问题。",
  "keywords": ["退款", "扣款", "发票"],
  "version": "1",
  "enabled": true,
  "path": "billing_support/SKILL.md"
}
```

`content` 不会出现在目录摘要里，服务器绝对路径也不会通过 summary 暴露。

### front matter 解析

`SKILL.md` 头部支持：

```markdown
---
name: 账单退款处理规范
description: 处理退款、扣款、发票和订阅问题。
keywords: 退款, 扣款, 发票
version: 1
enabled: true
---
```

当前支持的最小集合：

- `key: value`
- 单引号 / 双引号值
- 中文冒号，例如 `description: "退款：查询与到账"`
- `keywords` 用中文逗号、英文逗号或 `[a, b]` 列表
- `enabled` 支持 `true/false`、`1/0`、`yes/no`、`on/off`、`disabled`
- 文件 BOM 和 CRLF
- 没有 front matter 时，名称回退到一级标题，描述回退到首个非标题段落
- 没有标题时，名称回退到目录名

明确不支持嵌套 YAML、对象和数组嵌套；这些场景不属于当前 Skill 配置需要。

### 发现与校验规则

- 只扫描 `skills/*/SKILL.md`，不递归加载其他 Markdown。
- 隐藏目录（例如 `.draft/`）直接跳过。
- 目录名必须匹配：

  ```text
  ^[a-z0-9][a-z0-9_-]{0,63}$
  ```

- `SKILL.md` 或 Skill 目录是符号链接时拒绝加载，避免通过链接逃逸根目录。
- 根目录不存在时按空目录处理，不报错。
- 根路径存在但不是目录时记录一条错误。
- `enabled: false` 的 Skill 在目录中跳过，不进入 catalog。
- 单个 Skill 缺少 `description`、front matter 未闭合、字段重复、字段格式错误时，只记录到 `errors`，不影响其他有效 Skill。
- 目录按 `id` 排序，保证每次加载顺序稳定。

### 目录快照

每次 `load()` 都会：

1. 版本号加一；
2. 扫描并解析所有 `SKILL.md`；
3. 收集有效 Skill 和错误；
4. 按 `id` 排序；
5. 替换当前 `SkillCatalog` 快照。

返回的 catalog 可以直接用于后续：

- `GET /skills` 调试接口；
- system prompt 中的轻量目录；
- 模型选择 Skill 后按需加载正文；
- 热重载后的变化报告。

本 commit 还没有实现 `reload()` 的差异报告、正文缓存和资源读取；这些放在后续 commit。

### 新增能力

| 方法                                  | 作用                                                            | 是否读内容   |
| ------------------------------------- | --------------------------------------------------------------- | ------------ |
| `load_skill(skill_id)`                | 读取 `SKILL.md` 正文，并返回资源清单                            | 只读正文     |
| `list_skill_resources(skill_id)`      | 列出 `references/`、`templates/`、`scripts/` 下的文件路径和大小 | 不读内容     |
| `read_skill_resource(skill_id, path)` | 按路径读取单个资源文本                                          | 读取指定资源 |

`load_skill()` 返回的正文已经去掉 front matter；正文为空时抛 `SkillBodyError`。

### 数据结构

| 类型                         | 作用                                                           |
| ---------------------------- | -------------------------------------------------------------- |
| `SkillDocument`              | 一次正文加载结果：descriptor、body、truncated、resources       |
| `SkillResourceInfo`          | 资源清单项：相对路径、字节大小                                 |
| `SkillResource`              | 单个资源读取结果：skill_id、相对路径、content、大小、truncated |
| `SkillNotFoundError`         | Skill id 不在当前目录                                          |
| `SkillResourceNotFoundError` | 资源文件不存在                                                 |
| `SkillResourceAccessError`   | 资源路径非法、越界、非文本或符号链接                           |
| `SkillBodyError`             | Skill 正文为空                                                 |

`load_skill()` 的返回示例：

```python
SkillDocument(
    descriptor=SkillDescriptor(...),
    body="# 账单退款处理规范\n\n1. 确认订单。\n2. 说明退款时效。",
    truncated=False,
    resources=(
        SkillResourceInfo("references/refund-policy.md", 1024),
        SkillResourceInfo("templates/refund-reply.md", 512),
    ),
)
```

资源清单只包含路径和大小，不包含文件内容。

### 按需读取流程

```text
SkillManager.load()
  → 只扫描 SKILL.md 文件头
  → 生成 SkillCatalog

SkillManager.load_skill(skill_id)
  → 从 catalog 取 descriptor
  → 读取 SKILL.md 正文
  → 去掉 front matter
  → 返回正文 + 资源清单（不读资源内容）

SkillManager.read_skill_resource(skill_id, path)
  → 校验路径
  → 读取指定资源文本
  → 返回 content / truncated / size
```

### 正文缓存

正文缓存键是：

```text
SKILL.md 绝对路径 -> ((mtime_ns, size), body, truncated)
```

- 同一文件、同样的 `mtime_ns + size` 时直接复用正文，不重复读文件。
- 文件变化后，下一次 `load_skill()` 会按新的 stat 重新读取。
- `load()` 会清空正文缓存，避免目录重载后命中旧正文。
- 资源内容当前不做缓存，每次 `read_skill_resource()` 都重新读取，保证拿到最新内容。

### 安全边界

- 资源只能从 `references/`、`templates/`、`scripts/` 读取。
- 拒绝绝对路径。
- 拒绝 `..` 路径穿越。
- 拒绝隐藏目录和隐藏文件。
- 拒绝反斜杠路径，统一使用正斜杠。
- 资源 `resolve()` 后必须仍在 Skill 目录内。
- 拒绝资源符号链接；符号链接目录也不会进入资源清单。
- 正文和资源都有字符上限，超过时截断并标记 `truncated=True`。
- 资源解码后包含 NUL 字符时按二进制文件拒绝。
- 脚本只作为文本返回，不执行。

## 今天第三件事：Skills 热重载的完整流程

这次只做一件事：给 `SkillManager` 增加显式热重载。运行中的进程调用 `reload()` 后，会重新扫描 `skills/`，不重启服务就能拿到新增、修改、删除后的 Skill。

下面按“怎么触发 → 输入输出 → 从前到后做了什么 → 完整例子”说明。

### 一、怎么触发热重载

当前没有文件监听，也没有定时轮询；热重载是显式调用：

```python
report = manager.reload()
```

后续接入 `/skills/reload` 接口时，HTTP 请求最终也是调用这个方法。

`load()` 保留为兼容入口，内部同样走一次 `reload()`，然后返回最新 catalog：

```python
catalog = manager.load()
```

### 二、输入和输出

**输入**：

- `SkillManager.root_dir` 指向的当前磁盘目录；
- 目录下的 `skills/<skill_id>/SKILL.md`；
- 每个 `SKILL.md` 的 front matter 和文件头。

**输出**：

- `SkillReloadReport`：本次新增、更新、删除、未变化、错误、版本号、耗时；
- `manager.catalog`：被原子替换为最新目录快照；
- `manager.last_report`：最近一次重载报告；
- 旧的正文缓存被清空。

### 三、从前到后具体做了什么

1. **串行化重载**
   获取 `_reload_lock`，保证同一时间只有一个 `reload()` 在扫描和替换，避免两个重载互相覆盖版本号。

2. **保存旧快照**
   在 `_lock` 内读取当前 `_catalog` 和 `_version`，作为 `previous` 快照。此时读取方仍然可以正常使用旧目录。

3. **扫描新目录**
   在锁外扫描 `skills/*/SKILL.md`。扫描期间不持有读锁，已有请求不会被重载阻塞。

4. **解析轻量元数据**
   每个 `SKILL.md` 仍然只读文件头，解析 `name`、`description`、`keywords`、`version`、`enabled`。单个文件解析失败只进入 `errors`，不会影响其他 Skill。

5. **计算差异**
   比较 `previous` 和 `new_catalog`，得到：
   - `added`：新目录里多出来的 skill id；
   - `removed`：旧目录里有、新目录里没有的 skill id；
   - `updated`：两边都有，但元数据或文件 `mtime_ns / size` 变了的 skill id；
   - `unchanged`：两边都有且指纹没变的 skill id。

6. **原子替换快照**
   在 `_lock` 内一次性替换 `_catalog`、更新 `_version`、记录 `_last_report`。读取方要么看到旧快照，要么看到新快照，不会看到“扫描了一半”的目录。

7. **清空正文缓存**
   reload 后清空 `_body_cache`，避免文件内容变化但 stat 恰好没变时继续命中旧正文。下一次 `load_skill()` 会重新读取。

8. **返回重载报告**
   返回 `SkillReloadReport`，包含本次变化、错误、版本号、加载时间和耗时。

这次只补 Skill 内容，不改加载器逻辑，也不接 `/chat`。三个业务 Skill 都改成“轻量正文 + 按需参考 + 按需模板”的结构。

本 commit 没有在真实业务包里放 `scripts/`。加载器已经支持读取脚本文本，但真实脚本是否执行应由后续工具层决定，不能由 Skill 加载器自动执行。

### 三个 Skill 分别负责什么

| Skill id                   | 适用场景                                       | 正文里的资源指针                                                  |
| -------------------------- | ---------------------------------------------- | ----------------------------------------------------------------- |
| `billing_support`          | 退款、退款到账、重复扣款、发票、订阅、优惠券   | `references/refund-policy.md`、`templates/refund-reply.md`        |
| `technical_support`        | 登录失败、接口报错、配置、部署、超时、连接问题 | `references/error-codes.md`、`templates/troubleshooting-reply.md` |
| `general_customer_service` | 问候、订单物流、售前售后分流、情绪安抚、转人工 | `references/handoff-policy.md`、`templates/general-reply.md`      |

### 每个文件的作用和上下游

#### `skills/*/SKILL.md`

- **作用**：提供该 Skill 的入口说明、处理步骤、资源指针和禁止事项。
- **大概流程**：
  1. `SkillManager.load()` 读取文件头，生成 catalog；
  2. 用户或模型选中该 Skill；
  3. `SkillManager.load_skill()` 读取正文；
  4. 模型按正文步骤处理，需要细节时再读取资源。
- **输入**：catalog 中的 `id / name / description / keywords`，以及用户的当前问题。
- **输出**：简短操作步骤、资源路径、升级条件和禁止事项。
- **上游**：`core/skill_loader.py` 的目录层和正文层。
- **下游**：后续 `/chat` 的 system prompt 或 Agent 工具循环。

正文都控制在 800～900 字符左右，只放流程和指针，不放大段规则。

#### `skills/*/references/*.md`

- **作用**：存放详细规则、错误码、时效表、转人工条件等长内容。
- **大概流程**：
  1. 正文提示“需要时读取某个 reference”；
  2. 模型或调用方执行 `read_skill_resource()`；
  3. 资源内容进入当前上下文。
- **输入**：`skill_id + references/...` 相对路径。
- **输出**：该 Skill 的详细参考文本。
- **上游**：`SKILL.md` 正文里的资源指针。
- **下游**：模型在具体判断或回答时使用。

详细内容不会出现在 catalog，也不会在启动时加载。

#### `skills/*/templates/*.md`

- **作用**：存放回复结构、话术骨架和禁止表达。
- **大概流程**：
  1. 正文提示“需要组织回复时读取模板”；
  2. 执行 `read_skill_resource()`；
  3. 模型按模板组织回复。
- **输入**：`skill_id + templates/...` 相对路径。
- **输出**：回复模板文本。
- **上游**：`SKILL.md` 正文里的资源指针。
- **下游**：模型生成最终回复时参考。

模板不包含真实订单、退款或物流状态，避免把示例值当成事实。

#### `tests/test_skill_content.py`

- **作用**：验证真实 `skills/` 目录能被加载器正确发现，并确认正文、参考和模板的分层没有被破坏。
- **大概流程**：
  1. 直接指向仓库 `skills/`；
  2. `SkillManager.load()` 检查三个 Skill 无错误；
  3. 逐个 `load_skill()` 检查正文和资源清单；
  4. 逐个 `read_skill_resource()` 检查资源可读；
  5. 检查详细参考标记没有出现在 catalog 或正文里。
- **输入**：仓库内真实 Skill 文件和资源文件。
- **输出**：pytest 通过/失败结果。
- **上游**：由 `pytest` 收集执行。
- **下游**：保护后续 API 接入时不会误把详细手册塞回 catalog。

### 内容分层

- `SKILL.md` 正文只写：
  - 适用场景；
  - 处理步骤；
  - 资源使用路径；
  - 回复要求；
  - 禁止事项；
  - 升级条件。
- `references/` 写详细规则：
  - 退款时效、重复扣款、发票、订阅、优惠券；
  - 常见 HTTP 错误码和排查方向；
  - 转人工条件、交接摘要和紧急程度。
- `templates/` 写回复骨架：
  - 信息不足时怎么问；
  - 已确认信息时怎么答；
  - 转人工时怎么交接；
  - 禁止表达。
