## 今天第一件事：接入 Skills 渐进加载、自动选择与热重载 API

当前已将 Skills 接入 `/chat` 主链路：启动时只读取 YAML frontmatter，聊天时根据 description 自动选择，或通过 `/skill_id`、`skill_ids` 手动选择，选中后才加载正文。

### 已实现的加载链路

```text
启动创建应用
  → 读取 SkillSettings
  → Skills 开启时创建 SkillManager(strict_front_matter=True)
  → 扫描 skills/*/SKILL.md，只读取 YAML frontmatter
  → 遇到 frontmatter 结束分隔符即停止，不读取正文前缀
  → 建立 name + description 轻量目录（id 用于引用）

收到 POST /chat
  → 检查是否有手动选择
      ├─ 消息开头有 /skill_id，或传入非 null 的 skill_ids
      │   → 合并去重，校验 id 和数量，跳过自动选择
      └─ 没有手动选择
          → 先按已有规则检查幂等回执，可回放则直接返回
          → 模型仅根据 name + description 匹配用户消息
          → 校验返回的 skill_ids 属于候选目录且未超过数量上限
  → 仅加载选中的 SKILL.md 正文，缓存有效时复用
  → 组装 system：原角色 + 轻量目录 + 选中正文 + 记忆上下文
  → 调用回答模型，同时传入历史消息和当前问题
  → 按原有记忆流程提交本轮并返回回答
```

API 要求 frontmatter 包含非空的 `name` 和 `description`，不从正文回退。
模型选择和聊天目录只使用 id、名称和描述，keywords 不参与选择。
正文按配置限制字符数，截断时会标记；资源只列出路径和大小，不自动读取内容，也不执行脚本。
无记忆、有记忆和记忆读取失败三条聊天路径均已接入。

### 自动选择与手动选择

自动选择示例：

```json
{ "message": "我的订单被扣了两次钱，怎么办？" }
```

不传 `skill_ids` 或传 `null`，且没有开头的 Skill 命令时，调用选择模型做 description 语义匹配。
选择阶段不读取正文或资源。未匹配、超时、调用失败或返回非法结果时，不加载正文，继续普通回答。
自动选择最多额外调用一次模型，最多等待 8 秒；候选目录受字符预算限制，放不下的条目跳过。

手动选择示例：

```json
{ "message": "/billing_support 我的订单被扣了两次钱，怎么办？" }
```

也可以通过请求字段指定：

```json
{
  "message": "我的订单被扣了两次钱，怎么办？",
  "skill_ids": ["billing_support"]
}
```

- 支持消息开头连续指定多个命令，例如 `/billing_support /technical_support 问题内容`。
- slash 命令与 `skill_ids` 合并去重，手动选择跳过自动选择模型调用。
- 显式传 `skill_ids: []` 可关闭本轮自动选择；消息中有 slash 命令时仍执行手动选择。
- 发给本轮回答模型的问题去掉开头命令，原始消息保留在记忆和幂等回执中。
- 每轮重新选择 Skill，不将选中状态永久绑定到会话。

### 目录与热重载接口

`GET /skills` 返回 `enabled/count/skills/errors/version/loaded_at`，只包含元数据，不返回正文或资源内容。
Skills 关闭时返回空目录、版本 0。

`POST /skills/reload` 仅在 Skills enabled 和 debug 同时开启时注册，否则 HTTP 和 OpenAPI 均不提供该路由。

```text
修改、新增或删除 Skill 文件
  → POST /skills/reload
  → 在线程中重新扫描 frontmatter
  → 计算 added / updated / removed / unchanged
  → 原子替换目录快照并清空正文缓存
  → 返回变化报告、错误、数量、版本和耗时
  → 后续聊天使用新目录，选中后重新读取正文
```

重载只影响当前进程，多 worker 部署需逐进程重载或重启。

### 配置、错误与配套修改

- `core/config.py` 新增 `SkillSettings`：`enabled`、`root_dir`、`catalog_max_chars`、
  `body_max_chars`、`resource_max_chars`、`max_selected_skills`、`debug`。
- `core/skill_loader.py` 提供严格 frontmatter 读取、正文缓存和原子重载。
- `core/skill_selection.py` 提供 slash 解析、description 语义选择和选择结果校验。
- `api/main.py` 完成聊天注入、手动选择、自动选择及管理接口接入。
- 未知或已删除的手动选择返回 `404 skill_not_found`；正文不可用返回 `503 skill_unavailable`；
  手动选择超过数量上限返回 `422 too_many_skills`；只有命令、没有问题返回 `422 skill_message_required`。
- `.env.example` 和 README 已补充配置、调用示例、预算和错误说明；Dockerfile 已将 `skills/` 复制进镜像。
- Skills 和 debug 默认关闭；Skills 关闭时不创建管理器、不解析 slash、不增加模型调用，保留原聊天行为。

## 今天第二件事：前端工程 P0，并入仓库并搭好设计基线

## 今天第三件事：前端 P1，类型与接口层

本次新增文件及作用（路径相对 `frontend/`）：

- `src/types/api.ts`：集中定义聊天、健康检查、Skills 和记忆调试接口的请求、响应类型，对齐后端模型。
- `src/api/client.ts`：基于 axios 创建共用实例，提供 `requestJson()`，统一请求前缀、参数、超时、取消及错误转换。
- `src/api/errors.ts`：定义统一的 `ApiError`，维护错误码对应文案和是否可重试的判断。
- `src/api/index.ts`：统一导出请求工具、配置和错误处理工具。
- `src/services/chat.ts`：封装 `POST /chat`，支持传入取消信号和自定义超时。
- `src/services/health.ts`：封装 `GET /health` 健康检查。
- `src/services/skills.ts`：封装 `GET /skills` 技能目录和 `POST /skills/reload` 热重载接口。
- `src/services/memory.ts`：封装 `GET /memory/{session_id}` 记忆调试接口，携带 `user_id` 查询参数。
- `src/services/index.ts`：统一导出各业务接口，供页面调用。
- `src/lib/id.ts`：提供 `createRequestId()`，生成聊天幂等请求使用的 `client_request_id`。
- `.env.example`：说明前端 API 前缀 `VITE_API_BASE_URL` 和开发代理目标 `VITE_PROXY_TARGET` 的配置方式。

已有文件配套修改：`package.json` / `package-lock.json` 添加 axios 依赖；`vite.config.ts` 读取环境变量配置代理；`src/App.tsx` 改为通过 `getHealth()` 检查连接，并使用统一错误处理。

当前普通 JSON 接口统一走 axios；SSE 的 fetch 请求尚未实现，留到 P3。
