# 常见错误码参考

本文件是 `technical_support` 的详细参考，只在需要解释具体错误码或排查方向时读取。

## 一、错误码逐项解释

### 400 Bad Request

请求参数格式不正确、缺少必填字段、字段类型不匹配，或请求体不符合接口约定。

排查方向：

- 检查请求方法、URL、Content-Type；
- 检查必填字段和字段类型；
- 检查是否有额外的、接口不接受的字段；
- 查看响应体中的字段级错误信息。

### 401 Unauthorized

通常表示认证失败，不代表用户没有权限。

排查方向：

- API Key、Token 是否缺失或过期；
- 请求签名、时间戳是否正确；
- 是否使用了对应环境的 Key；
- 是否把测试环境凭证用到了生产环境。

不要要求用户公开完整密钥，只展示前后几位即可。

### 403 Forbidden

通常表示已认证，但没有访问该资源的权限。

排查方向：

- 账号角色和资源权限；
- IP 白名单；
- 套餐或接口开通状态；
- 资源归属和租户隔离。

### 404 Not Found

请求路径或资源不存在。

排查方向：

- URL 是否拼写正确；
- 是否缺少路径前缀或版本号；
- 资源 ID 是否属于当前账号；
- 接口是否已经下线或迁移。

### 409 Conflict

通常表示请求与当前资源状态冲突，例如重复创建、版本冲突或并发修改。

排查方向：

- 是否重复提交；
- 是否使用幂等键；
- 资源当前状态是否允许该操作；
- 并发写入是否需要重试或加锁。

### 429 Too Many Requests

请求被限流。

排查方向：

- 是否超过 QPS 或日调用额度；
- 是否多个实例共用同一个 Key；
- 是否没有退避策略；
- 是否需要申请更高配额。

建议使用指数退避，不要立即无限重试。

### 500 Internal Server Error

服务端处理异常。500 不能直接证明是用户侧问题。

排查方向：

- 收集 request_id、接口路径、请求时间；
- 收集请求参数摘要和响应体；
- 查看服务端日志中的异常栈和依赖错误；
- 判断是否由数据库、缓存、第三方服务或参数触发。

### 502 Bad Gateway

网关或代理从上游收到无效响应。

排查方向：

- 上游服务是否启动；
- 反向代理配置和超时；
- 上游是否返回了非 HTTP 响应；
- 是否存在服务重启或发布。

### 503 Service Unavailable

服务暂时不可用，常见于过载、维护或依赖不可用。

排查方向：

- 服务健康检查；
- 限流和熔断状态；
- 数据库、缓存、消息队列是否可用；
- 是否正在发布或扩容。

### 504 Gateway Timeout

网关等待上游响应超时。

排查方向：

- 上游处理时间；
- 代理和网关超时配置；
- 慢查询、锁等待或第三方接口延迟；
- 是否需要异步化或拆分请求。

## 二、连接和配置问题

### 连接超时

优先排查网络、DNS、防火墙、代理、证书、服务端限流。稳定复现时建议提供最小复现请求；偶发超时时记录发生频率和请求峰值。

### TLS / 证书错误

检查证书是否过期、域名是否匹配、系统时间是否正确、代理是否替换了证书。

### CORS 错误

确认请求来源是否在后端允许列表、预检请求是否通过、响应头是否包含正确的 `Access-Control-Allow-Origin`。

### Webhook 回调失败

确认回调地址可公网访问、签名校验正确、响应状态码和响应体符合平台要求，并保留回调日志和重试记录。

## 三、安全边界

- 不要求用户提供完整 API Key、Token、密码、验证码或私钥；
- 不根据用户描述编造服务端日志；
- 不建议删除生产数据、关闭安全校验或重装系统；
- 涉及生产变更时，先提示备份、评估影响和回滚方案。
