# 技术支持回复模板

## 一、信息不足时

```text
我先帮你定位。为了缩小范围，请补充：
1. 具体错误信息或错误码；
2. 发生时间和是否持续复现；
3. 使用环境：浏览器/App/服务端、操作系统、版本号；
4. 影响的用户或接口范围；
5. 最近是否升级版本、改配置、换网络或改密钥。

如果方便，请提供相关日志片段或 request_id，不要发送完整密钥。
```

## 二、401 / 403

```text
这个错误更像认证或授权问题，暂时不能直接断定是服务端故障。

请先确认：
1. Token 或 API Key 是否过期；
2. 是否使用了对应环境的凭证；
3. 请求签名和时间戳是否正确；
4. 当前账号是否有该资源的权限；
5. 是否配置了 IP 白名单或套餐限制。

请不要在公开渠道粘贴完整密钥，只提供前后几位即可。
```

## 三、500 / 502 / 503 / 504

```text
这类错误表示服务端或链路异常，需要结合日志才能定位。请提供：
1. request_id；
2. 接口路径和请求时间；
3. 请求方法、状态码和响应体摘要；
4. 最近是否发布、重启或变更配置；
5. 影响范围是单个用户、单个接口还是全站。

在拿到这些信息前，我不能确认具体根因。
```

## 四、超时或连接失败

```text
请先按低风险顺序检查：
1. 网络和 DNS 是否正常；
2. 是否有代理、防火墙或证书拦截；
3. 服务端是否限流或过载；
4. 是否只有特定接口或特定地区复现。

如果稳定复现，请提供 curl 或最小复现请求；如果是偶发问题，请记录发生频率和请求峰值。
```

## 五、升级人工或二线技术

```text
如果这是生产环境大面积故障、支付链路异常、数据丢失、权限异常或安全事件，建议立即升级人工或二线技术，并保留最近一次失败请求的 request_id 和日志时间点。
```
