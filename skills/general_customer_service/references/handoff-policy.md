# 转人工与交接参考

本文件是 `general_customer_service` 的详细参考，只在判断是否转人工或准备交接摘要时读取。

## 一、什么时候建议转人工

- 用户明确要求人工客服；
- 用户已经多次表达同一问题仍未解决；
- 涉及投诉、威胁拒付、法律或监管表述；
- 涉及实际退款、补偿、发票作废或重开、大额账单；
- 生产环境故障影响多名用户、支付链路异常、数据丢失或权限越权；
- 涉及密钥泄露、异常登录、疑似攻击等安全事件；
- 当前角色缺少查询或处理权限，继续回答只能猜测。

## 二、转人工前先做什么

1. 先确认用户的核心诉求，不要只转一句“帮你转人工”。
2. 汇总已经确认的信息，避免用户重复描述。
3. 说明为什么需要转人工，以及转交后大概会处理什么。
4. 不要承诺人工一定能在某个具体时间内解决。

## 三、转人工交接摘要清单

交接摘要应包含：

- 用户 id 或会话 id（如果系统已有）；
- 用户核心诉求；
- 已确认的订单号、交易号、错误码或时间范围；
- 已经尝试过的处理步骤；
- 当前阻塞点；
- 是否涉及资金、投诉、安全或生产故障；
- 建议接手的角色：账单、技术、二线技术或人工客服。

不要把完整密钥、密码、验证码、完整银行卡号写进交接摘要。

## 四、紧急程度参考

| 场景 | 建议优先级 |
| --- | --- |
| 生产大面积不可用、支付异常、数据丢失 | 高 |
| 重复扣款、实际退款争议、发票作废 | 中高 |
| 单个用户登录问题、配置问题 | 中 |
| 一般售前咨询、物流查询 | 普通 |
| 用户只是问候或表达感谢 | 不需要升级 |

## 五、交接后的表达

```text
我已经把目前确认的信息整理好了：
- 你的诉求：……
- 已确认的信息：……
- 目前需要核验的点：……

这个问题需要人工/账单/技术同事继续处理，我会把上述信息一起转交，避免你重复描述。
```

不要用“已经解决”“马上就好”代替真实交接状态。
